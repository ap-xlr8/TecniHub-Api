# Seguridad

No reportes vulnerabilidades públicamente. Para este repositorio académico, contacta de forma privada al responsable del proyecto y comparte pasos mínimos de reproducción. No incluyas secretos en issues, logs o capturas.

Los informes deben indicar impacto, versiones afectadas, condiciones de reproducción y mitigación sugerida. El responsable registra recepción, severidad, corrección y evidencia. Prioridad operativa: críticas y altas primero; medias y bajas se evalúan con el contexto y la exposición reales.

Las opciones de Secret Scanning, Push Protection y CodeQL dependen de la visibilidad y el plan de GitHub y deben verificarse en la configuración del repositorio una vez que exista remoto.
